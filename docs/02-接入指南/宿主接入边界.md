# 宿主接入边界

本文解释 IAM、qs-server、qs-ai 如何把通用消息合同映射到本地业务。SDK 负责可复用机制，宿主仍拥有业务事务、事件定义、幂等、执行许可、资源、迁移与生产运维。下面的跨仓库地图固定源码 commit，说明可定位的实现，不代表该 commit 已部署或完成业务验收。

## 责任表

| 问题 | SDK 负责 | 宿主负责 |
|---|---|---|
| 事务提交与投递意图 | 原事务 appender、冲突判断、标准状态/存储操作 | 业务写入与意图使用同一笔事务；回滚、迁移、连接池 |
| 消息身份与 wire | 通用身份、指纹、codec/protected wire | event ID 来源、事件 schema、scope、topic 映射与首次不可变字节 |
| 发送与结算 | 发布结果分类、领取/栅栏、NSQ 结算、失败中转 | 原业务回执核验、业务结果判定、持久失败审计 |
| 重复与未知结果 | 保持原身份/字节、技术重投和有限状态操作 | 业务幂等、逻辑失败预算、是否允许重试副作用 |
| 生命周期 | 显式 Run/Start/Subscribe、Drain/Close 合同 | 装配、监督、停止顺序/预算、资源实际退出证明 |
| 观测与运维 | 通用 Observer/快照与有界分类 | 指标前缀、阈值、渠道、授权、拓扑、发布与恢复验收 |

Outbox 放在宿主业务数据库中。独立 SDK 仓库不意味着独立服务、中央事务库或 SDK 自持有 MySQL/Redis/Mongo；通用状态与驱动要求见[事务与 Outbox](../01-核心设计/事务与Outbox.md)。Redis signaling 是最佳努力提示，其失联通过持久扫描或宿主回查恢复，不能成为新的事实源。

## IAM：授权事实与策略通知

参考基线：`c8fc1fe61a32056368148e232e96d32763c15ba5`。

IAM 的 AuthZ 用例在原 Unit of Work 内写授权事实、递增 PolicyVersion 并追加事件；提交后 reload 当前实例。其 StandardStager 绑定原 GORM 事务，把 IAM 的事件、scope 与 payload 映射为通用 Message，Store/Relay/NSQ 负责后续投递。消费者核对版本并重载 IAM 权威快照，消息不是授权事实本身。

- [IAM StandardStager](https://github.com/FangcunMount/iam/blob/c8fc1fe61a32056368148e232e96d32763c15ba5/internal/apiserver/infra/mysql/eventoutbox/standard_stager.go)：原事务绑定与 PolicyVersion 事件映射。
- [IAM 事件组合根](https://github.com/FangcunMount/iam/blob/c8fc1fe61a32056368148e232e96d32763c15ba5/internal/apiserver/container/platform/eventing.go)：目录、标准模式与资源注入。
- [IAM Relay 运行监督](https://github.com/FangcunMount/iam/blob/c8fc1fe61a32056368148e232e96d32763c15ba5/internal/apiserver/infra/messaging/reliable_runtime.go)：Run 返回后的监督和停止排空。
- [IAM 版本消费](https://github.com/FangcunMount/iam/blob/c8fc1fe61a32056368148e232e96d32763c15ba5/internal/apiserver/application/authz/policypublication/service.go)：已加载版本幂等和快照重载。
- [IAM 事件目录](https://github.com/FangcunMount/iam/blob/c8fc1fe61a32056368148e232e96d32763c15ba5/configs/events.yaml)与[授权写入正文](https://github.com/FangcunMount/iam/blob/c8fc1fe61a32056368148e232e96d32763c15ba5/docs/02-业务模块/03-AuthZ/03-关键链路-授权写入与受管Assignment.md)。

IAM 文档拥有多实例广播、授权快照新鲜度、撤权失效、安全失败方向和业务时限。SDK 文档不承诺某个权限在固定秒数内生效，不复制 IAM 角色/范围模型或 bootstrap 迁移操作单。

## qs-server：双业务库、多个执行角色

参考基线：`2ccc2de44bbd45e26d29e7e130da518cc32426f0`。

QS 在 Mongo 答卷事务和 MySQL 评分/任务事务中分别持久化相应事件。它们是两段宿主事务，不是 SDK 提供的一笔跨 MySQL/Mongo 分布式事务。消费者按 QS 原业务身份接单与幂等，报告、Run、Task 和通知的业务权威状态仍在 QS。

- [Mongo StandardStager](https://github.com/FangcunMount/qs-server/blob/2ccc2de44bbd45e26d29e7e130da518cc32426f0/internal/apiserver/infra/mongo/standardoutbox/stager.go)与[MySQL StandardStager](https://github.com/FangcunMount/qs-server/blob/2ccc2de44bbd45e26d29e7e130da518cc32426f0/internal/apiserver/infra/mysql/standardoutbox/stager.go)：原事件到 SDK 意图的适配。
- [Worker SDK 接线](https://github.com/FangcunMount/qs-server/blob/2ccc2de44bbd45e26d29e7e130da518cc32426f0/internal/worker/integration/messaging/runtime_sdk.go)与[业务 handler 注册](https://github.com/FangcunMount/qs-server/blob/2ccc2de44bbd45e26d29e7e130da518cc32426f0/internal/worker/handlers/registry.go)：Transport 到业务处理的边界。
- [Worker 重试与 hold](https://github.com/FangcunMount/qs-server/blob/2ccc2de44bbd45e26d29e7e130da518cc32426f0/internal/worker/integration/messaging/retry_hold.go)：原业务结果、技术失败与宿主恢复入口。
- [QS 事件责任正文](https://github.com/FangcunMount/qs-server/blob/2ccc2de44bbd45e26d29e7e130da518cc32426f0/docs/03-基础设施/event/10-架构与责任边界.md)与[Outbox 链路](https://github.com/FangcunMount/qs-server/blob/2ccc2de44bbd45e26d29e7e130da518cc32426f0/docs/03-基础设施/event/30-Outbox可靠出站链路.md)。

QS 文档拥有业务事件表、Task 提醒的收件人/有效期/抑制、报告完成定义、权限缓存、服务停止顺序、积压时限、人工重放批准和业务对账。SDK 提供通用原行重排，但不能据此判断报告不存在、通知未发出或模型可以再次调用。

## QS 与 qs-ai：命令及持久回执

qs-ai 参考源码基线：`c977cb9cd8301c46fb260441aee6ea5b7a3ec3f2`。该地图涉及独立 AI MQ 宿主实现，应按对应发布说明核对可用范围；不把源码存在解释为切流完成。

受回执约束的命令/事件先在宿主原事务中写入原意图与 wire，PUB 后仍等待业务回执。接收方在持久接单/幂等记录和回执意图提交后才能结算 Broker delivery；发送方必须认证并核对原身份、内容摘要和正确阶段后才能 Confirm。具体冻结配置、准入、执行/恢复和模型结果判定属于 QS/qs-ai。

- [QS AI MQ 运行装配](https://github.com/FangcunMount/qs-server/blob/2ccc2de44bbd45e26d29e7e130da518cc32426f0/internal/apiserver/infra/aibridge/messaging_runtime.go)。
- [QS 回执型存储接线](https://github.com/FangcunMount/qs-server/blob/2ccc2de44bbd45e26d29e7e130da518cc32426f0/internal/apiserver/infra/mysql/aibridge/messaging.go)、[relay](https://github.com/FangcunMount/qs-server/blob/2ccc2de44bbd45e26d29e7e130da518cc32426f0/internal/apiserver/infra/mysql/aibridge/messaging_relay.go)、[receiver](https://github.com/FangcunMount/qs-server/blob/2ccc2de44bbd45e26d29e7e130da518cc32426f0/internal/apiserver/infra/mysql/aibridge/messaging_receiver.go)。
- [qs-ai asyncio 装配](https://github.com/FangcunMount/qs-ai/blob/c977cb9cd8301c46fb260441aee6ea5b7a3ec3f2/src/qs_ai/bootstrap/messaging.py)。
- [qs-ai 原事务存储](https://github.com/FangcunMount/qs-ai/blob/c977cb9cd8301c46fb260441aee6ea5b7a3ec3f2/src/qs_ai/infrastructure/persistence/mysql/messaging.py)、[receiver](https://github.com/FangcunMount/qs-ai/blob/c977cb9cd8301c46fb260441aee6ea5b7a3ec3f2/src/qs_ai/infrastructure/workflow_transport/mq_receiver.py)、[relay](https://github.com/FangcunMount/qs-ai/blob/c977cb9cd8301c46fb260441aee6ea5b7a3ec3f2/src/qs_ai/infrastructure/workflow_transport/mq_relay.py)。

SDK 不接管 LangChain/LangGraph 的执行图、Checkpoint、容量、候选配置、业务重试许可或未知模型结果；也不因消息超时、NSQ 重投或 ACK 丢失重新生成模型任务。qs-ai 单服务/单容器/单进程的资源与恢复约束由宿主保持，Python 接入不能自动扩大为多进程执行架构。

## 宿主交付清单

接入完成应能在宿主文档回答：

1. 哪一笔业务事务同时保存了事实与原意图，失败是否共同回滚？
2. event ID、scope、schema、wire 与路由由谁定义，技术重投如何取回原字节？
3. 消费者何时持久接单、何时 Ack，重复和未知副作用由什么权威记录判断？
4. 旧未完成记录、回退镜像、加法 schema 与配置窗口如何交接？
5. 谁停止入口、等待 handler/Relay/driver、再关闭数据库，超时后如何保留恢复责任？
6. 指标、告警、人工治理和真实业务验收证据在哪里，使用哪个版本与时间窗口？

SDK 通用检查通过只能证明其合同覆盖范围，不能替宿主完成上述交付。现行正文解释机制；部署实例、镜像摘要、生产水位和验收百分比留在各宿主的版本化发布/运维记录中。
