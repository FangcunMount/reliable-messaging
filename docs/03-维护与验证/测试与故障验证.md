# 测试与故障验证

本文说明如何验证SDK合同、如何区分测试替身与真实依赖，以及故障试验的结论边界。适用于当前 Go 与 Python预发布源码；版本级执行结果见[发布索引](../releases/README.md)。本文列出可执行入口，不声称这些命令已在每次阅读时执行。

## 证据分层

可靠消息的关键问题在完成点之间。验证不仅检查接口返回，还需检查原事务、原持久行、原字节、重复物理投递与消费者效果。一次CI成功只能证明其实际执行范围。

| 层次 | 能证明什么 | 不能据此推导什么 |
| --- | --- | --- |
| 身份与 golden fixture | 指纹、wire、历史兼容和跨语言一致性 | 原数据库事务或真实 Broker 投递 |
| 单元 / 显式替身 | 策略分支、资源所有权、并发和迟到回调处理 | 网络断开、驱动提交、Broker磁盘保证 |
| 真实适配器 | 原 MySQL/Mongo事务、claim栅栏、NSQ确认与重投 | 宿主领域幂等、权限和模型副作用正确 |
| 真实故障 / 独立进程 | 确认丢失、SIGKILL、重启扫描、持久预算 | 未执行的故障域、完整宿主回退或容量目标 |
| 构建并安装发布制品 | wheel远离源码可导入、资产与源码绑定 | Release已发布或宿主已采用 |
| 宿主与业务验收 | 原接单、具体效果、回执、冻结配置与恢复 | SDK所有版本或所有运行组合均通过 |

## 常规 Go 检查

从仓库根目录运行：

```sh
make check
make lint
```

`check` 执行离线文档检查、格式、vet、全量默认测试和race；文档检查需要 Python 3.11+ 标准库。`lint` 安装固定版本工具，需要工具获取条件；两者不会执行 `integration` 或 `redis_integration` 构建标签下的真实依赖用例。公开API或wire变更应同时检查[兼容测试](../../tests/compatibility/)、[架构依赖测试](../../tests/architecture/)和[身份向量](../../contracts/fixtures/identity-vectors.json)。

## 真实双库与 NSQ

```sh
make integration
make subscription-integration
```

入口是[完整隔离脚本](../../scripts/integration.sh)和[订阅专项脚本](../../scripts/nsq-subscription-integration.sh)。需要 Go、Python 3、Docker以及支持 `up --wait` 的Compose。脚本拒绝远程 Docker / `DOCKER_HOST` 覆盖，以随机项目和一次性数据库运行；依赖缺失或Docker不可用应失败，不能把跳过当作成功。不得将这些脚本的数据库地址改为宿主或生产配置。

完整入口包括真实业务/Outbox提交回滚、双Store、时区、领取公平性、丢确认、进程崩溃、迟到结算、原行重排、真实发布器生命周期、固定旧新标签交接与专用Broker重启。订阅专项集中验证直接地址/lookupd、首消息channel预备、失联/恢复、失败中转确认丢失与持久录入失败后重排。精确当前集合以脚本和测试源码为准，见[集成目录](../../tests/integration/README.md)。

脚本清理仅删除本轮Compose项目和构建目录；SIGKILL或主机崩溃可能留下资源，应按项目标签确认所有权后处理。不能用全局 Docker prune代替项目清理。

Redis提示需另运行真实适配器检查：

```sh
RM_SIGNAL_REDIS_ADDR=127.0.0.1:6379 go test -race -count=1 -tags redis_integration ./signaling/redis
```

该地址必须是专用测试Redis。断开/重连验证的是提示transport，业务正确性仍须由宿主TTL、回源或持久扫描证明。

## Python检查与安装制品

从 `python/` 运行：

```sh
uv sync --locked --extra nsq
uv run --locked --extra nsq ruff check src tests
uv run --locked --extra nsq ruff format --check src tests
uv run --locked --extra nsq mypy src
uv run --locked --extra nsq pytest -q --junitxml=results.xml
uv build
```

完整测试要求专用 `RM_M7_MYSQL_URL`、`RM_MQ_NSQ_TCP`、`RM_MQ_NSQ_HTTP`；Go回执型预算探针另需 `RM_MQ_DURABLE_TEST_DSN`。测试会建表、写入和清理专用记录，不能连接业务数据库。实际参数、专用NSQ大小与内存设置、工具链组合和报告检查以[Python工作流](../../.github/workflows/python.yml)为准。

工作流校验报告非空、零fail/error/skip，并把wheel装到独立环境后再次运行必需测试，记录源码、tree与资产摘要。`uv build` 本身不等于wheel已验证，CI上传artifact也不等于GitHub Release或PyPI发布。

## 按失败窗口定位用例

| 失败窗口 | 验证点与入口 | 接受的限制 |
| --- | --- | --- |
| 业务事实写入后、事务提交前退出 | [Python事务/进程](../../python/tests/test_mysql.py)、Go双Store真实提交/回滚 | 证明所测原事务；不外推跨库原子性 |
| 提交后唤醒丢失 | Go Relay轮询、[Python扫描恢复](../../python/tests/test_mysql.py) | 发现速度由宿主轮询/容量决定 |
| publish接受但确认或写回丢失 | Go crash/late relay、[NSQ掉线](../../transport/nsq/handoff_disconnect_integration_test.go) | 可重复投递，保留原身份/字节；不声称exactly-once |
| 老claim迟到写回 | [late relay](../../tests/integration/late_relay_test.go)、Store集成测试 | 依赖数据库栅栏；无法强行终止不合作的宿主callback |
| 终态handoff确认丢失、录入失败 | [NSQ订阅试验](../../tests/integration/nsq_subscription_test.go)、[持久审计](../../tests/integration/nsq_failure_audit_test.go) | 失败中转可重复；宿主录入必须幂等 |
| 回执丢失、接收者重启 | [Python回执型MySQL](../../python/tests/test_durable_mysql.py) | SDK fixture不替代真实业务接收者 |
| 成功final ACK反复重发、held后重复到达 | [Go预算](../../tests/integration/ackbudget/mysql_test.go)、Python durable测试 | 保留原失败预算和hold，不推断历史计数含义 |
| NSQ正常stop/start与强杀 | [Broker进程探针](../../tests/integration/brokerrestart/main.go)、Python durable测试 | 正常退出刷新不等于SIGKILL安全；确认过的内存消息可丢失 |
| 旧新版本交接 | [固定标签脚本](../../scripts/integration.sh)、[双版本探针](../../tests/integration/versionhandoff/) | 部分降级不维护新失败计数；不能称全状态回退均兼容 |
| protected wire / 大小边界 | [跨语言合同](../../python/tests/test_mq_contracts.py)、[Go protected](../../wire/protected/) | 校验和不认证；正文引用读取与业务授权仍由宿主验证 |

## 如何记录结论

执行记录至少包含精确源码/标签、依赖版本或镜像摘要、参数、实际命令、退出码、非空报告、原行状态和本轮拥有的资源。替身参与的用例应明确其替代哪一段，故障以实际触发点命名。

“期望Broker内存消息在SIGKILL后丢失，实际确实丢失”是已知边界的表征成功，不是崩溃可靠性通过。正常运行、完整积压恢复、生产容量、权限和未知模型调用都需宿主独立证据，不能从SDK fixture或Release资产代签。

详细采集与排查回链[观测与故障处置](./观测与故障处置.md)；环境支持回链[兼容与升级](./兼容与升级.md)。
