# 兼容与升级

本文说明 Go 与 Python 适配器的支持范围、版本边界和升级条件。适用于当前预发布线；已经发布的版本、源码和资产见[版本索引](../releases/README.md)。支持范围不等于宿主已升级或生产业务已验收。

## 兼容对象与结论

一次升级需要分别比较 API、消息 wire、持久状态、驱动和宿主装配。包版本相同不表示它们具有相同的业务确认边界；不同语言也不共享一套数据库状态机。技术重投必须继续使用原身份、原字节，未知副作用由宿主核实。

| 兼容对象 | 权威来源 | 核对内容 |
| --- | --- | --- |
| Go API / Python API | 公开源码、类型与包版本 | 调用方式、错误、生命周期和资源所有权 |
| 消息身份与 wire | `message`、`wire`、跨语言 fixture | 原 ID、指纹、原字节、历史信封、扩展字段与认证上下文 |
| 持久状态 | 各 Store、schema 与索引定义 | 所有未完成状态、claim 栅栏、失败预算和原行审计关联 |
| 驱动与依赖 | `go.mod`、`python/pyproject.toml`、锁文件 | 事务活跃性、确认丢失、超时、调度时间及停止行为 |
| 宿主行为 | 宿主组合根、handler、回执与恢复合同 | 消费幂等、业务重试授权、冻结配置、迁移和回退执行者 |

详细的[身份与协议](../01-核心设计/消息身份与协议.md)、[事务与 Outbox](../01-核心设计/事务与Outbox.md)和[确认分层](../04-设计决策/002-发布确认与业务回执分层.md)是升级判断的前提。SDK版本不能替代宿主 payload 的 `schema_version`。

## 加法迁移与旧未完成记录

宿主负责原业务数据库内的表、集合和索引迁移；SDK不执行自动DDL，也不拥有独立 MySQL、MongoDB 或 Redis 服务。参考结构仍在[标准 MySQL schema](../../storage/mysql/schema.sql)、[Mongo Store](../../storage/mongo/store.go)及[回执型 schema](../../delivery/mysql/schema.sql)，两种 SQL 表不能混用。

升级先盘点未完成状态和其责任执行者，再安装加法列或索引。新写入者启动之前验证读取、追加、领取和结算所需的完整结构。回退窗口内禁止删除旧读者仍需要的字段或重算原指纹。Mongo历史记录缺少诊断字段时，能读取消息和能正确展示状态是两项不同验证。

Go `v0.1.0` 到 `v0.2.1` 的真实双版本试验表明：普通 pending 行可以交接，旧 Store 却不维护新增 `failure_count`，因此重试诊断与失败预算不能安全直接降级。这是降级限制，不应被“旧版仍能发送”覆盖。

`v0.3.0-m6.2` 加入 MySQL `RequeueConfirmed` 与原行审计列。它只重排已确认原行：宿主必须核验缺失效果、原身份、期待版本和持久审批，并在同一事务中保存审批记录。它不授予业务重试许可，也不能代替消费者幂等。

`v0.3.0-mq-ai.1` / Python `0.2.0a1` 增加独立回执型合同；`mq-ai.2` / `0.2.0a2` 修正 receipt-free final ACK 的持久失败预算。旧计数可能包含成功发布，补丁无法推断其中哪些是真失败，不会重置计数或自动恢复 held 行。旧未完成行必须按其原合同处置。

## 升级和回退步骤

1. 固定语言包版本、对应源码和制品摘要，检查宿主没有非预期 `replace` 或本地源码覆盖。
2. 比较 API、wire、表/索引、状态、密钥及驱动；明确仍未完成的原行、未知副作用与执行者。
3. 由宿主安装加法迁移，先做真实事务和兼容读取验证，再启动新写入者。SDK包升级不自行触发宿主迁移。
4. 用目标标签执行受影响的 SDK 隔离检查及宿主接单、幂等、回执和停止路径。测试替身不替代原消费者与宿主恢复证据。
5. 切换前阻止不兼容执行者竞争同一记录；停止顺序和预算由宿主按[生命周期合同](../01-核心设计/生命周期与恢复.md)制定。
6. 回退前逐状态核验旧执行者是否理解现有记录、回执、失败预算与 wire。旧镜像能启动、队列为空或一条请求成功不能代替兼容责任交接。
7. 切换后用原 ID 对账业务事实与消费者回执，保留配置/版本及观察时间。出现未知结果时进入核对，不生成新消息掩盖原责任。

标准 MySQL调度 `DATETIME(6)` 使用显式UTC数字，Mongo保存绝对时刻；业务显示和运维使用UTC+8。升级不得批量平移已有调度列或重写 `occurred_at`。时间核验见[timezone集成测试](../../tests/integration/mysql_timezone_test.go)。

## 版本承诺与重新评估

当前仍为0.x / alpha预发布。Go和Python各自固定版本，变更需明确迁移办法，不因某个预发布成功而声称 Go v1 稳定合同成立。计划中的v1兼容原则为：保留已承诺API、身份和持久状态；弃用先提供替代与迁移，破坏性删除进入新的主版本。

新增数据库、驱动、Broker、多进程Python所有权或动态拓扑时，应先提供对应事务、迟到回调、重启、确认丢失与停止证据，再扩大矩阵。相关取舍见[独立语言版本 ADR](../04-设计决策/004-语言与包独立版本.md)。
