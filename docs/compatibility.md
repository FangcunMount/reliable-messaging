# 兼容与升级策略（M6-01 候选）

截至 2026-09-29（UTC+8），最新预发布版本为 `v0.3.0-m6.2`；IAM 与 qs-server 当前主线仍固定 `v0.3.0-m6.1`，只有 QS 的未合并恢复草稿固定 `m6.2`。本文区分已测组合与尚待验收的支持范围，**不宣称 v1.0 已稳定**；M5 业务流、M6 回退、容量与旧组件退役仍有未完成门槛。

| 维度 | 当前基线 | 声明边界 |
| --- | --- | --- |
| Go | SDK 与 IAM 声明 Go 1.25.9；qs-server 声明 1.25.12；SDK 建议工具链 1.25.12。 | 1.25.9 是源码声明下限，不是两宿主完整实测下限；当前跨宿主构建使用 1.25.12。 |
| MySQL | IAM、qs-server 现役均为 8.0.36。SDK 在一次性 8.0.36 上通过原事务／领取栅栏、同身份并发、加法迁移和时区集成测试。 | 不据此保证每个 8.0 补丁或完整 IAM／QS 回退。 |
| MongoDB | qs-server 现役为 7.0.31；SDK 在同版一次性 replica set 上通过原事务重入、未知提交、到期公平扫描和有界积压扫描测试。 | 选定隔离路径与一份成功业务样本都不能推出最低服务端版本、生产服务端故障或完整回退兼容。 |
| NSQ | 现役 broker 与隔离故障测试均使用 nsqd 1.3.0；SDK 依赖 `go-nsq` 1.1.0。 | 计划中的 v1.0 传输范围仅 NSQ。内存队列参数下，发布确认不证明消费效果或进程强杀后的 broker 持久性。 |
| 驱动 | SDK 固定 `go-sql-driver/mysql` 1.9.3、`mongo-driver` 1.17.6、GORM 1.30.0。 | 更换驱动后须重验事务、确认、时间和恢复，不自动扩展支持范围。 |

宿主负责业务事务、本地 Outbox 表／集合和迁移、Relay 生命周期、消费幂等及业务重试授权。SDK 在技术重试中保留原应用消息 ID 与不可变 wire 字节。发布确认丢失须记为结果未知；重复物理投递不得新增业务效果。更换 broker 或看到 Outbox `published` 都不能自动填平事务提交到消费者效果之间的缺口。

## 升级与降级

1. 两宿主固定 SDK 发布标签。升级前比较公开 Go API、wire fixture、消息身份、必需列与索引、状态转换和驱动版本；运行 SDK 集成验证及受影响的 IAM、qs-server 事务、Relay、消费与回退路径。
2. 先由宿主完成加法 schema／索引变更，再启动新写入者；回退窗口内旧执行者仍须能读取当前结构。逐状态指定 `pending`、`publishing`、`retry_wait`、`quarantined` 和失败中转消息的责任执行者，交接前停止竞争写入者。
3. `v0.2.1`→`v0.3.0-m6.1` 不改变 SDK MySQL／Mongo Store 或 Relay schema，但新增目录、wire、Subscriber、Provisioner 和托管 Publisher API；仍须核对宿主数据与消费者。新失败预算记录**不支持直接交给 `v0.1.0` 降级处理**，因为旧版不维护新增的失败元数据。
4. `v0.3.0-m6.1`→`v0.3.0-m6.2` 新增 MySQL `Appender.RequeueConfirmed` 和参考建表 DDL 的 `manual_replay_request_id`、`manual_replay_version` 两列；现有发布／领取／Relay 主路径没有改动。此方法**只重排已经确认的原行**，调用前由宿主核验缺失的业务效果、持久审批及原身份，并在同一事务中写入审批记录。SDK 不自动迁移宿主数据库；使用前须核对加法列已安装（qs-server 的标准表迁移 84 已包含），否则让数据库报错，不省略审计。旧版执行者对新增的恢复审计及重新排队状态尚无完整降级演练，恢复请求或待 Relay 行未结案时，不得仅回滚 SDK／镜像就把责任交给旧版。
5. 宿主镜像回退后重新核对真实业务效果与授权新鲜度。镜像可启动、当前队列为空或一份测评成功，均不能代替逐流恢复证明。

v1.0 前公开 API 仍属预发布范围；变更必须说明迁移办法并验证 IAM／qs-server 的调用者。旧通用 API 只有在受支持宿主迁至替代入口、回退窗口结束后才能删除。v1.0 发布后，在整个 v1 期间保留已承诺的公开 API、wire 身份与持久状态兼容；不兼容删除须进入新主版本并提供迁移说明。此规则不承诺无限期保留无人使用的 `component-base` 旧入口。

Python 与 RabbitMQ 尚未实现，不列入本发布线支持范围。RabbitMQ 迁移仍须独立决策。表中的生产补丁版本是已观察基线，不能自动外推至未来补丁，也不能跳过 M6-03／06 的故障和容量验收。
