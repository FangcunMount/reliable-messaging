# ADR 004：语言与包独立版本

状态：已采用。适用：Go模块 `github.com/FangcunMount/reliable-messaging` 与Python发行包 `fangcun-reliable-messaging` / import `reliable_messaging`。实际发行见[版本索引](../releases/README.md)。

## 问题与约束

统一可靠消息需要一致的身份、字节与确认含义，不要求两种语言的类型、线程模型和存储实现完全相同。Go SDK提供标准租约Store与Relay，Supervisor由宿主实现；Python原表adapter服务单进程原任务/回执，后来增加可选NSQ和独立回执型MySQL。

强行同步版本号会使用户误以为两边能力、失败恢复和制品同步发布；只复制代码又会让wire与身份漂移。

## 备选与选择

| 方案 | 代价 |
| --- | --- |
| Go/Python共享版本号和一次发布 | 语言专属修改阻塞另一包，版本相同易被误认合同等价 |
| 独立仓库、独立协议样例 | wire/身份兼容更易漂移，跨语言测试难形成一条证据 |
| 同仓库共享语义/fixture，独立语言发行 | 发布管理需标明范围，但各包可按已验证能力迭代 |

采用第三项。Go用根模块tag，Python用 `python/v...` tag及自身 `pyproject.toml`版本。共同维护身份向量、wire/安全规则及跨语言golden测试；语言专属生命周期与事务入口分别说明。

## 不变量与代价

- 源码main、本地tag、GitHub Release资产和宿主实际采用分别核验。任何一项不能自动证明下一项。
- `pyproject.toml`是源码包版本；不证明wheel已构建、资产已上传或包已进入生产。
- 同一wire不代表同一表或调度并发保证。Python不因Go接口存在而获得多进程claim/lease能力。
- 默认Python核心不依赖可选NSQ extra；Go SDK不依赖Python运行时或宿主仓库。
- 独立补丁仍须保留共同身份/字节合同，跨语言不兼容变化必须具名版本与迁移说明。

用户须选定语言/合同和固定版本，而不是安装“最新main”来猜能力。版本索引会增加维护成本，但这是避免发布状态和宿主验收混淆的必要记录。

## 重新评估条件与证据

只有包无法独立消费、或语言变体确实共享一个必须同步升级的协议主版本时才重新讨论联动发行；协议版本与包版本仍需区分，不隐式重算历史指纹。
